# 账号切换第一版

入口在「我的」顶部账号卡片内，昵称右侧的灰色「⇄ 切换」按钮；右上角只保留设置。头像和昵称仍进入个人主页。未登录时可从登录按钮下方进入已保存账号，资料加载中或失败时也保留切换入口。Android 和 iOS 共用这套界面与 `AccountRepository`，每个站点分别保存账号列表；同一个 UID 再次登录会更新原记录。

## 使用行为

- 添加账号前保存当前登录态，打开原有的原生登录页；网页登录、邮箱验证和两步验证继续使用原有流程。取消添加会返回原账号。
- 添加流程由导航栈判断是否退出；账号列表为返回预览而被预先加载、验证码刷新或键盘弹出时继续保留登录页。登录表单与账号列表使用应用现有的分组卡片样式。
- 切换时先关闭所有旧页面、清除其 ViewModel，停止前台请求与后台下载，再替换 Cookie。目标账号必须通过服务器返回的 UID 检查。
- 登录失效、身份不匹配或网络失败会恢复原账号的登录态和草稿。保存过程中的恢复记录用于处理切换中途的进程退出。
- 帖子草稿和回复草稿按账号归档；私信草稿沿用现有 UID、会话指纹和过期句柄保护。浏览记录和阅读位置沿用 UID 隔离。
- 移除当前账号会退出登录，移除其他账号保留当前会话。移除会删除该账号保存的登录态和草稿；UID 浏览记录仍按现有规则保留。
- 站内消息通知只轮询当前账号。主题、代理、图床、关键词、追踪规则和主动订阅的抽奖提醒继续使用原有设备设置。

第一版的离线下载仍只有一套存储。账号选择器会在已有下载时确认清除；切换成功、进入添加账号的登录流程和移除当前账号会清除这些下载。目标账号验证失效或网络失败而回退时保留下载。

## 多账号自动签到

账号列表中每个账号都有独立的自动签到开关；设置页的开关和签到方式对应当前账号。升级前的设备签到设置只迁移给原账号，新添加账号默认关闭；切换账号不会改变其他账号的设置。

前台触发和系统后台任务会依次处理已开启的账号，使用各自独立的 Cookie 和网络仓库，不切换当前浏览账号，不覆盖其个人资料缓存。每次先验证服务器返回的 UID；某个账号失效会提示重新登录，并继续处理其他账号。添加账号期间暂停签到，切换账号会取消正在执行的批次。

签到沿用每天的完成记录、30 分钟重试间隔及每日三次尝试上限，按 UID 去重。手动和自动签到对同一 UID 串行处理，避免同时提交；一个账号成功不会掩盖其他账号需要网络重试的结果。后台获取的新 Cookie 只更新对应的保存记录，已移除或重新登录的账号不会被旧任务写回。

Android 使用 WorkManager，iOS 使用 BGTaskScheduler；后台执行时机仍由系统决定。站内消息通知继续只检查当前账号。

## 登录态存储

Android 的账号文件通过现有 `KeystoreSecretCipher` 使用 Android Keystore 下的 AES-GCM 密钥加密。Cookie 快照使用 AndroidX WebKit `GET_COOKIE_INFO`，保留域名、路径、过期时间、Secure、HttpOnly 和 SameSite 等属性，并把相对有效期转换为绝对时间。系统 WebView 不支持该能力时提示更新，基本退出登录仍可使用。

WebView 的 Cookie 属性导出与服务器的 `Set-Cookie` 有一个区别：仅限当前主机的 Cookie 也会带 `domain`，只有真正的域 Cookie 才带前导点。保存时会先还原这个区别，再交给 OkHttp 解析；否则清理可能删除另一个域作用范围的 Cookie，遗留旧登录。快照显式记录主机范围，兼容此前导出的记录，也避免把后台签到响应的 `Set-Cookie` 与 WebView 导出混淆。替换前确认旧登录已清除；共享账号仓库也会在进入添加前确认已经退出，失败则恢复原账号与草稿。

iOS 同时替换 `NSHTTPCookieStorage` 与 `WKHTTPCookieStore`。账号文件位于排除备份的 Application Support 子目录，启用 `NSFileProtectionCompleteUntilFirstUserAuthentication` 的系统数据保护加密。这里沿用自签安装可用的文件保护方案，原因见 `KeychainLegacySecrets`。没有保存账号密码。

Cookie 属性通过 Foundation 的 XML plist 保存，读取端自动识别 XML 和有效的二进制 plist。
Kotlin 2.4.20 的集合桥接会在重复读取时重建 Objective-C 包装，而 Foundation 的二进制写入器
按对象身份记录引用；原生回归发现数组元素因此被写成了数组自身，读取报 Cocoa 3840。
实际编码往返与独立生成的二进制样例分别覆盖新快照保存和旧格式读取。

启动恢复也会处理已经落盘的损坏快照。只有明确的 Cookie 编码或结构错误才进入隔离：
先在原受保护账号库中保留恢复记录、添加记录和原账号草稿，写入可重复执行的空恢复记录，
随后清除不可信会话和活动文件，回到添加登录流程。清理中途退出时，下次只重放空记录，
不会再次解析坏快照。已知 UID 的账号标记为需登录；重新登录后恢复该 UID 自己的草稿，
无法确定归属的草稿不会交给新登录账号。移除已知账号也删除其隔离记录。
普通平台存储错误、账号库读取失败或隔离记录写入失败仍报告存储错误，不跳过或覆盖原数据。

页面的恢复命名空间随账号切换持久化，防止 Android 进程重建时恢复另一个账号的导航预览。iOS 保留系统根控制器，在 UIKit 转场结束后释放旧账号的所有页面。

## 保存失败重试

原生表单登录完成后会等待账号保存。保存失败时停留在提示页，可点「重试保存」继续当前
登录会话；账号列表也提供重试入口。重试保存不会再次提交用户名和密码。

## 验证

核心回归测试包括 Cookie 有效期与属性保留、账号草稿切换、取消添加、登录失效和身份不符回退、保存失败、进程中断恢复、会话 Cookie 重启恢复、网页登录直接换号、旧请求取消、私信草稿过期句柄及移除账号后继续编辑。多账号签到覆盖失效隔离、身份检查、每日去重、重试优先、运行中关闭或移除账号、Cookie 更新归属，以及手动与自动签到的竞争。账号文件读取失败时禁止使用空数据覆盖原文件；签到设置写入失败时保留原设置并报告存储错误。

主机范围解析和清理失败仍进入添加的两项回归先在旧实现上失败，修复后通过；导航回归覆盖等待验证期间、取消预测返回手势后继续保留添加页。用户已在 Android 手机上验证账号添加和切换，并确认合并测试包的功能正常。
